## Findings

### CT-01 — Medium — Final CTA analytics do not match the destination

- Routes/state: `/about`, `/en/about` final primary CTA; `/`, `/en` final Telegram CTA, all widths.
- Evidence: `src/build.mjs`, `finalCTA()` unconditionally applies `data-event="order_start"` to the primary link. `src/about-view.mjs` calls it with `/solutions` or `/en/solutions`, so visiting the catalogue is recorded as an order start. The homepage secondary link points to Telegram but has no `telegram_click` annotation; other existing Telegram links use that event.
- Impact: the new conversion band inflates order-start measurement for About visitors and omits the new homepage Telegram action. It does not disclose PII or affect order persistence.
- Acceptance: allow the shared CTA to choose/omit its primary event according to the destination; retain order-start for an actual order link. Annotate the Telegram secondary link with the existing Telegram event. Verify the rendered UA/EN links and event behaviour without following a real external destination.
- Status: **closed after revision**. Independently rechecked the parameterized `finalCTA()` and About's explicit `primaryEvent:null,secondaryEvent:null`. Parsed fresh built HTML for `/`, `/en`, `/about`, `/en/about`: order links retain `order_start`, homepage Telegram links have `telegram_click`, and About catalogue/contact links have neither misleading event. [ct-01-closure.json](ct-01-closure.json) records exact rendered mappings and HTML SHA-256. No browser, external navigation or send was needed for this markup-level correction.

### CT-03 — High — About image ratio styles violated the accepted CSP

- Origin: root's legacy browser console diagnostic. The initial source review did not catch the interaction between new inline figure styles and the unchanged response policy.
- Routes/state: `/about` and `/en/about`, all widths, loading the seven founder photos.
- Evidence: `server/wsgi.py:65` retains `style-src 'self'`. The initial About photo renderer placed `--about-desktop-ratio` and `--about-mobile-ratio` on each figure's inline `style` attribute. The browser therefore rejected those seven declarations. This is a CSP error and can defeat intended image-space reservation before lazy media decoding.
- Source fix independently verified: both built About pages now have no inline `style` attributes in their main content. All seven desktop/mobile aspect-ratio pairs are declared in local `src/about.css` under the corresponding `data-founder-photo` selector, appear in generated `site/assets/style.css`, and numerically match the exact pinned approved derivatives. The server/CSP file is byte-identical to recovery; no policy relaxation was made.
- Evidence: [ct-03-source-closure.json](ct-03-source-closure.json). Inspected root's `smoke/final-batch-check.json`: both About locales at 390 px record empty error lists and identical initial/final document height after media decoding (UA 14643 px, EN 14431 px). This bounded smoke is supporting evidence, not the full matrix.
- Acceptance: final current-build UA/EN console diagnostics and target-width matrix record no CSP/page errors; all About images remain non-clipped with reserved mobile/desktop geometry. Preserve the accepted CSP.
- Final status: **closed**. The same frozen revision's About navigation/media reports contain zero console/CSP/page errors; all seven mobile/desktop derivatives load, and the 36-row diagnostic report is clean. External ratio CSS remains source-bound and the accepted CSP unchanged. See `content-technical-final.json` for exact hashed report paths.
